# ИИ-стилист

Лендинг для записи в закрытое тестирование цифрового гардероба.

Исходники сайта находятся в `app/`, схема базы — в `db/schema.ts`, миграции — в `drizzle/`.
Используются React, Vinext и Cloudflare D1. Интеграция Sites сохранена в `vite.config.ts` и `worker/`.

## Локальная разработка

Требуется Node.js 22.13 или новее. В Windows используйте `npm.cmd`, если выполнение PowerShell-скриптов отключено.

1. Установите зависимости: `npm.cmd run install:ci`.
2. Соберите проект: `npm.cmd run build`.
3. Примените SQL-миграции из `drizzle/` по порядку к локальной базе, например:

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_fantastic_wolfsbane.sql
```

4. Для проверки админки создайте игнорируемый `.dev.vars` с `ADMIN_EMAIL=seedy@sites.test`.
5. Запустите `npm.cmd run dev`. Локальный вход: `/signin-with-chatgpt?return_to=/admin`.
6. Интеграционная проверка локального сервера: `node --experimental-strip-types scripts/smoke-test.mjs`. Скрипт создаёт только локальную тестовую заявку с префиксом `smoke_`.
7. Проверка маршрутов: `node --experimental-strip-types scripts/route-test.mjs`.

Применённые миграции не запускайте повторно и не изменяйте: добавляйте новые через `npm.cmd run db:generate`.
Локальная и размещённая базы независимы. Локальные заявки и `.dev.vars` не публикуются.

## Заявки

`POST /api/applications` принимает имя, возрастную группу, Telegram, необязательный телефон и явное согласие.
Telegram нормализуется; повторные заявки с тем же именем пользователя не создают дубликаты.
Есть серверная проверка полей, проверка Origin, ограничение размера запроса, honeypot и ограничение частоты по хешу IP.

Страница `/admin` и выгрузка `/api/admin/export` доступны только пользователю ChatGPT, чей подтверждённый email совпадает с секретом Sites `ADMIN_EMAIL`.
CSV содержит BOM для Excel и защиту от формул. Заявки не доступны в публичном API.
Адрес для вопросов и удаления заявки: https://t.me/DuImaran.

## Размещение

Sites ID сохраняется в `.openai/hosting.json`. Повторно создавать Site не нужно.
Публикация выполняется через Sites после сборки, синхронизации исходников и упаковки. Секреты задаются через настройки окружения Sites.
Не меняйте аудиторию проекта без отдельного указания владельца.

## Изображения

Иллюстрации созданы встроенным ImageGen и оптимизированы в WebP. Пути и полные промпты: [ASSETS.md](ASSETS.md).
Фотография на первом экране иллюстрирует идею цифрового гардероба.
В разделе «Маршрут дня» работает отдельная локальная модель демонстрационного гардероба (11 вещей). Она перебирает допустимые комплекты для трёх этапов, сохраняет закреплённую вещь и учитывает заданную погоду, дресс-код, ходьбу, число изменений и дополнительные вещи. Это демонстрация будущего направления: фотографии пользователей и прогнозы она не обрабатывает. Конфликт сухих кед с дождём показывается явно.

Дополнительные поля заявки `platform`, `priority` и `route_summary` необязательны. Маршрут отправляется только после отдельной отметки пользователя. Существующие заявки сохраняются: миграция `0001` добавляет nullable-поля.

`POST /api/events` увеличивает дневные обезличенные счётчики. Контакты, IP и идентификаторы посетителей в этих счётчиках не хранятся. Для ограничения частоты запросов используется временный хеш сетевого адреса. Интерфейс ограничивает повтор события в рамках сессии; это события, а не уникальные посетители. В админке нельзя трактовать их как точную конверсию или подтверждённые скачивания файла.

Новая визуальная система использует бирку, нить и инвентарные номера. Одежда в лаборатории — SVG-элементы интерфейса в `app/wardrobe/garment.tsx`. Сохраняемая карточка маршрута — SVG, формируемый на устройстве; она не загружается на сервер.

В текущем интерфейсе демо виден один выбор погоды и сразу три комплекта. Планы и постоянная вещь находятся в закрытом по умолчанию блоке настроек. Номера вещей и переключатели этапов убраны. Стили демо вынесены в `app/wardrobe/lab.css`. Цветовые токены: `--accent: #c83f25` для текста и основных кнопок, `--accent-vivid: #e64c2e` для ярких деталей; фон демо — тёплый `#fff1e9`. Контраст молочного текста `#f8f6f0` на основном цвете кнопки составляет примерно 4.63:1.

Сравнение с первичными описаниями продуктов на 12.11.2026: [Acloset](https://www.acloset.app/), [Whering](https://whering.zendesk.com/hc/en-gb/articles/5917678596383-How-does-Whering-build-my-outfit-suggestions), [Indyx](https://www.myindyx.com/). Гардероб, подбор под погоду, планирование, капсулы и статистика уже встречаются у конкурентов. Маршрут внутри одного дня с объяснением переходов — гипотеза для проверки в интервью, не заявление об отсутствии аналогов на всём рынке.
